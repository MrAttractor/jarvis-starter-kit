3. Détail technique par domaine
3.1 Authentification &amp; sécurité
Fonctionnalités à construire
▸ Inscription par email + mot de passe (hash bcrypt)
▸ Connexion OAuth2 (Google, Apple Sign-In)
▸ Gestion de session JWT avec refresh token (expiration 15 min / 30 jours)
▸ Système de pseudonymat : dissociation complète nom réel / pseudo affiché
▸ Vérification email par lien unique (SendGrid ou AWS SES)
▸ Réinitialisation de mot de passe sécurisée
▸ Logs d&#39;acceptation CGV horodatés en base (RGPD)
▸ Suppression de compte et droit à l&#39;oubli (cascade en base)

3.2 Vérification vidéo (KYC)
Composants techniques requis
▸ Accès caméra natif (WebRTC sur web, Camera API sur mobile)
▸ Détection de vivacité (liveness detection) : clignement, rotation tête, sourire
▸ Envoi sécurisé de la séquence vidéo chiffrée vers le backend
▸ Stockage temporaire sur S3 avec TTL 24h (suppression automatique post-validation)
▸ Interface de modération humaine (back-office) : file d&#39;attente, approve / reject
▸ Notification push / email du résultat à l&#39;utilisateur (validé ou refusé + motif)
▸ Statut de profil : en attente / vérifié / refusé — visible sur les cartes profil
▸ Intégration possible d&#39;une API tierce (Veriff, Onfido) pour la couche IA

3.3 Algorithme de matching conversationnel
Composants à développer
▸ Chatbot guidé (arbre de décision + NLP) pour collecter les préférences utilisateur
▸ Extraction de traits : valeurs, style de vie, projets de vie, humour, centres d&#39;intérêt
▸ Vectorisation des profils (embedding) pour calcul de similarité cosinus
▸ Score de compatibilité multi-dimensionnel (valeurs 30%, style de vie 25%, projets 25%, autres
20%)
▸ Mise à jour dynamique du score en cours de conversation

▸ Stockage des vecteurs de profil en base (pgvector sur PostgreSQL ou Pinecone)
▸ API de recommandation : retourne les N profils les plus compatibles non encore vus
▸ Actualisation du modèle selon les interactions (acceptation / refus / messages)

3.4 Système de mise en relation
Workflow et composants
▸ Envoi d&#39;une demande de mise en relation avec message d&#39;introduction (280 car. max)
▸ Statuts de demande : envoyée / vue / acceptée / déclinée (avec possibilité de décliner sans
justification)
▸ Notification push + badge en temps réel à la réception d&#39;une demande
▸ Consentement mutuel obligatoire avant ouverture de la conversation
▸ Protection anti-spam : limite de X demandes simultanées par utilisateur
▸ Back-office de supervision : détection de comportements abusifs
▸ Système de signalement (report) et blocage d&#39;utilisateur
▸ Log de toutes les mises en relation pour audit de modération

3.5 Messagerie temps réel
Infrastructure de chat
▸ WebSocket (Socket.io) pour messages instantanés
▸ Historique des conversations stocké en base (PostgreSQL)
▸ Statuts de lecture : envoyé / livré / lu
▸ Notification push (FCM pour Android, APNs pour iOS) quand l&#39;app est en arrière-plan
▸ Limite initiale : messagerie texte uniquement (V1) — photos et vocaux en V2
▸ Chiffrement des messages en transit (TLS) et au repos (AES-256)
▸ Option de suppression d&#39;un message / d&#39;une conversation
