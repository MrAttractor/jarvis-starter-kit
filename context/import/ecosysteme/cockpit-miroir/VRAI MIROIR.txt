# MIROIR — Kit de déploiement

Agent d'apprentissage de l'écosystème Attractor. Observe les décisions de Mac Arthur (VALIDÉ/REJETÉ), reconstitue sa méthode, l'injecte dans Attractor Assists.

## Ordre de déploiement (depuis VS Code)

### 1. Base de données — `01_schema.sql`
Supabase > SQL Editor > colle et exécute `01_schema.sql`.
Crée : table `decisions`, table `methode_miroir`, vue `referentiel_actif`, RLS.

### 2. Edge Function — `02_edge_function_miroir.ts`
```bash
# dans le dossier de ton projet Supabase
supabase functions new miroir
# remplace le contenu par 02_edge_function_miroir.ts
supabase secrets set CLAUDE_KEY=sk-ant-xxxxx
supabase functions deploy miroir
```
> `SUPABASE_URL` et `SUPABASE_SERVICE_ROLE_KEY` sont injectés automatiquement, ne pas les set.

### 3. Réveil automatique — `03_cron.sql`
Supabase > SQL Editor > colle `03_cron.sql`.
Remplace `<PROJECT_REF>` et `<ANON_OR_SERVICE_KEY>`.
MIROIR se réveille toutes les 30 min (ajustable). Réveil à vide = gratuit (aucun appel Claude si rien à traiter).

### 4. Interface smartphone — `04_interface_smartphone.html`
Remplace `<PROJECT_REF>` et `<SUPABASE_ANON_KEY>` en haut du `<script>`.
Déploie sur Netlify (drag-and-drop du dossier, ou via Git).
Ouvre sur ton smartphone → valide/rejette au pouce, ajoute des décisions, vois les points "À arbitrer".

## Circuit complet

```
Smartphone (interface) → table decisions (VALIDE/REJETE)
       ↓ (toutes les 30 min)
Edge Function MIROIR → lit décisions non traitées
       ↓
API Claude (Haiku 4.5) → extrait le principe (JSON strict)
       ↓
table methode_miroir → référentiel "Méthode Mac Arthur"
       ↓
(plus tard) injecté dans Attractor Assists
```

## Garde-fous intégrés

- **Anti-hallucination** : pas de champ `preuve` rempli = principe rejeté automatiquement.
- **Contradiction non tranchée seul** : remontée dans `a_arbitrer` → visible sur le smartphone.
- **Coût maîtrisé** : max 5 décisions par réveil, modèle Haiku 4.5, réveil à vide gratuit.

## Coût estimé
~6 $/mois pour un usage actif (≈20 décisions/jour). Voir le récap pour le détail.

## Sécurité — à faire avant la production
- L'interface utilise la clé `anon`. Active une vraie authentification (Supabase Auth) pour que seul Mac Arthur puisse valider/rejeter.
- Ne mets jamais la `service_role_key` dans le HTML frontend (uniquement dans l'Edge Function).
- La `CLAUDE_KEY` reste dans les secrets Supabase, jamais dans le navigateur.
